# Transferring the Project to the Workstation via Git

This guide moves the **code** to the workstation through Git, and rebuilds the
**environment** there from `requirements.txt`. Data, outputs, the database, and
the virtual environment are NOT transferred through Git (they are excluded by
`.gitignore`); they stay local on each machine.

---

## One-time setup on your laptop

From your THESIS project root (the folder that contains `pipeline/`, `solve.py`,
`data/`, `output/`, the venv, etc.):

```bash
# 1. Initialise the repository
git init

# 2. Confirm .gitignore is in place BEFORE the first add, so the venv/data/output
#    are never staged. Verify nothing large is about to be committed:
git status            # data/, output/, venv/, *.duckdb must NOT appear

# 3. Stage and commit the code only
git add .
git commit -m "Initial commit: micro-CT analysis pipeline"
```

If `git status` shows `data/`, `output/`, the venv, or `*.duckdb`, stop — the
`.gitignore` is not being read. Make sure this repo's `.gitignore` is at the root
before `git add`.

---

## Push to a Git host

Create an empty repository on your Git host (GitHub, or Shell's internal
GitLab/GitHub). Then:

```bash
git remote add origin <repository-URL>
git branch -M main
git push -u origin main
```

---

## On the workstation (one time)

```bash
# 1. Clone the code
git clone <repository-URL>
cd <repository-name>

# 2. Recreate the environment
python -m venv .venv
source .venv/bin/activate          # or .venv\Scripts\activate on Windows
pip install --upgrade pip
pip install -r requirements.txt

# 3. Create local data/output folders and copy data in
#    (data is NOT in Git — transfer it separately, e.g. scp/rsync/shared drive)
mkdir -p data output
#    place your .am volumes and the saturation .xlsx into data/

# 4. Run
python -m pipeline
```

---

## Ongoing: keeping laptop and workstation in sync

After editing code on your laptop:

```bash
git add -A
git commit -m "describe the change"
git push
```

On the workstation, before running:

```bash
git pull
```

The environment only needs rebuilding when `requirements.txt` changes; otherwise
`git pull` is enough.

---

## Transferring the DATA (separately from Git)

Because data is excluded from Git, copy it directly to the workstation once:

- If you reach the workstation by **SSH**:
  `rsync -av ./data/ user@workstation:/path/to/project/data/`
  (or `scp -r ./data user@workstation:/path/to/project/`)
- If you reach it by **Remote Desktop**: use a shared folder or a drive both
  machines can see.

Outputs and the database are regenerated by running the pipeline on the
workstation, so they never need transferring.
